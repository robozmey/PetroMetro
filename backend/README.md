### Формат JSON

Схема метро содержит два массива: `stations` и `lines`.

- `stations`: `id` (уникальный положительный ID), `name` (название), `x`, `y` (координаты), `year` (необязательный год открытия).
- `lines`: `id` (уникальный положительный ID), `name` (название), `color` (цвет `#RRGGBB`), `stations` (ID станций в порядке следования).

Все ID станций в линиях должны существовать в `stations`. Название и slug города хранятся отдельно в таблице `cities`.

### Запуск

При запущенном Docker:

```powershell
docker compose up -d db
docker compose run --rm migrate
cd backend
$env:DATABASE_URL = 'postgres://podzemka:podzemka@localhost:5433/podzemka?sslmode=disable'
go run ./cmd/seedschemas
go run ./cmd/api
```

### Добавление города

Из папки `backend` при настроенном `DATABASE_URL`:

```powershell
go run ./cmd/importcity -file kazan.json -name "Казань" -slug kazan
```

Команда проверяет схему и сохраняет город в PostgreSQL. При повторном запуске с тем же slug существующая схема обновляется.

### Импорт станций из Overpass

`importstations` превращает JSON-выгрузку Overpass в формат схемы метро. Порядок станций внутри каждой линии строится жадным алгоритмом ближайшего соседа по географическим координатам. Это эвристика: после импорта следует проверить развилки и пересадки, поскольку одной близости координат недостаточно, чтобы определить топологию линий.

```powershell
go run ./cmd/importstations -input "C:\Users\ZonMyCar\OneDrive\Документы\metroSpb.txt" -output "$env:TEMP\saint-petersburg-stations.json"
```

Результат создаётся отдельно; команда не изменяет исходную выгрузку и не загружает JSON в базу автоматически.

### Добавление города из Overpass через сайт

На странице раскройте «Добавить город из Overpass JSON», укажите название, slug и выберите JSON-файл, экспортированный из Overpass. Нажмите «Показать предпросмотр», проверьте количество найденных станций и линий, затем подтвердите создание. После сохранения город появляется в списке выбора.

Запрос для Overpass Turbo (Казань; выполнить через **Run**, затем экспортировать результат как JSON):

```overpass
[out:json][timeout:60];
{{geocodeArea:Казань}}->.city;
(
  node["station"="subway"](area.city);
  node["subway"="yes"](area.city);
);
out body;
```

Подходит стандартный ответ Overpass с массивом `elements`. Импортёр также принимает экспорт, состоящий только из последовательности JSON-объектов станций (как в файле «Текстовый документ.json»), включая завершающие запятые. При этом файл должен содержать синтаксически завершённые объекты; позиции строк и редакторные маркеры в файл попадать не должны.

Frontend отправляет файл в `POST /api/cities/preview-import` как multipart-поле `file`. Endpoint ограничивает загрузку 10 МБ, выполняет тот же парсер, что и CLI, и возвращает предварительную схему без записи в базу. После подтверждения UI отправляет готовую схему в `POST /api/cities`; API отклоняет уже занятый slug с `409 Conflict`. Автоматические координаты нормализуются по границам выгрузки, поэтому перед использованием схемы их следует проверить и при необходимости скорректировать.

Для создания города через HTTP API отправьте `POST /api/cities` с JSON-объектом. Slug должен состоять из строчных латинских букв и цифр, разделённых одиночными дефисами.

```powershell
$body = @'
{
  "name": "Казань",
  "slug": "kazan",
  "stations": [
    { "id": 1, "name": "Кремлёвская", "x": 100, "y": 120, "year": 2005 }
  ],
  "lines": [
    { "id": 1, "name": "Центральная", "color": "#123456", "stations": [1] }
  ]
}
'@
Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/cities -ContentType 'application/json' -Body $body
```

Новый slug создаётся с ответом `201 Created`; существующий slug обновляется с `200 OK`. Некорректный JSON, slug или схема возвращают `400 Bad Request`. Схема проверяется по тем же правилам, что и при импорте JSON.
